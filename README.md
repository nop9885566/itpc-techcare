# itpctakecare

ระบบบันทึกและติดตามการดูแลนักเรียนรายเคสสำหรับครูที่ปรึกษาและผู้ดูแล โรงเรียน ITPC

## ความสามารถ

- ปฏิทินและติดตามเคส พร้อมประวัติการอัปเดตและลายเซ็น
- จัดเก็บนักเรียนแยกตามปีการศึกษา เพื่อรักษาประวัติข้ามปี
- ผู้ดูแลระบบ (admin) และครูผู้ดูแลเป็นคนละคนและใช้คนละบัญชี: admin จัดการบัญชีและข้อมูลนักเรียน ส่วนครูผู้ดูแลบันทึกและดูแลเคส พร้อมแก้ไขข้อมูลบัญชีของตนเองได้
- ปิดข้อมูลนักเรียนด้วยเวลาปิดใช้งาน (`timestamptz`) โดยเก็บประวัติเดิมและไม่นำข้อมูลที่ปิดแล้วกลับมาแสดง
- ส่งออกรายงาน PDF และ Excel

## เริ่มต้นใช้งาน

1. ติดตั้งแพ็กเกจ:

   ```bash
   npm install
   ```

2. คัดลอก `.env.example` เป็น `.env.local` และกำหนดค่าจริง:

   ```env
   SUPABASE_URL=https://your-project-id.supabase.co
   SUPABASE_ANON_KEY=...
   ```

   `SUPABASE_ANON_KEY` ต้องเป็น anon key ของโปรเจกต์เดียวกับ URL ระบบคงล็อกอินชื่อ/PIN ของแอป ไม่ใช้ Supabase Auth, JWT หรือ server key; ฐานข้อมูลตรวจ opaque session token แบบสุ่มใน header กับ hash ที่จัดเก็บไว้ก่อนอนุญาต RLS

3. รันไฟล์ SQL ใน Supabase SQL Editor ตามลำดับ:

   1. `sql/01_schema.sql`
   2. `sql/02_rls_policies.sql`
   3. `sql/03_functions.sql`
   4. `sql/04_seed.sql` (ใช้เฉพาะข้อมูลตัวอย่าง)

   `01_schema.sql` รองรับตารางเดิมและเพิ่มปีการศึกษา/เวลาปิดใช้งานให้กับข้อมูลเก่าโดยอิงวันที่สร้าง

4. สร้างบัญชีผู้ดูแลระบบแยกจากบัญชีครูผู้ดูแลใน Supabase SQL Editor โดยเปลี่ยนชื่อและ PIN ตัวอย่างในคำสั่งให้เป็นค่าจริงก่อนรัน:

   ```sql
   insert into public.caretakers (name, pin_hash, role)
   values (
     'ชื่อผู้ดูแลระบบ',
     extensions.crypt('เปลี่ยนเป็น PIN ตัวเลข 4-6 หลัก', extensions.gen_salt('bf')),
     'admin'
   );
   ```

   ชื่อบัญชีเข้าสู่ระบบโดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ ส่วน PIN เป็นตัวเลข 4–6 หลักและตรวจตามค่าที่ตั้งไว้ อย่าใช้ชื่อบัญชีหรือ PIN ของครูผู้ดูแลซ้ำ และอย่าเปลี่ยนบทบาทบัญชีครูเดิมเป็น admin บัญชีตัวอย่างครูจาก `04_seed.sql` ใช้ PIN `1234` ให้เปลี่ยน PIN หรือสร้างบัญชีจริงก่อนนำไปใช้ ต้องมีบัญชี admin ที่ใช้งานได้อย่างน้อยหนึ่งบัญชี ระบบป้องกันการปิดหรือลดบทบาทของ admin คนสุดท้าย

5. เริ่มเซิร์ฟเวอร์:

   ```bash
   npm run dev
   ```

   เปิด [http://localhost:3000/takecare](http://localhost:3000/takecare)

## สิทธิ์และความปลอดภัย

- หน้าจอใช้ชื่อ/PIN และเซสชัน opaque แบบสุ่มที่ผูกกับบัญชีฝั่งฐานข้อมูล เก็บในคุกกี้ `HttpOnly` และหมดอายุใน 12 ชั่วโมง
- ทุก Server Action ที่อ่านหรือแก้ไขข้อมูลตรวจสอบเซสชันกับบัญชีที่ยังใช้งานอยู่; การจัดการบัญชีและนักเรียนจำกัดไว้เฉพาะ `admin`
- Supabase client ใช้ `SUPABASE_ANON_KEY` เท่านั้น; ไม่มีการใช้ `service_role` key
- RLS อนุญาตเฉพาะ opaque session ที่ active และ role ตรงกับบัญชีที่ยังใช้งานอยู่; คำขอ anon ทั่วไปไม่มีสิทธิ์อ่านหรือแก้ไขข้อมูล และนักเรียนที่ปิดแล้วจะไม่ถูกเลือก
- Opaque session token อยู่ในคุกกี้ `HttpOnly`, เก็บเป็น hash ในฐานข้อมูล และแนบจาก Server Actions ไปยัง PostgREST; ไม่มีการเชื่อ `localStorage` หรือ role ที่ client ส่งมา

## การส่งออก

- Excel รายเดือนมีชีตข้อมูลเคส ประวัติการอัปเดต และข้อมูลผู้ลงนาม
- Excel รายบุคคลมีชีตข้อมูลนักเรียน เคสทั้งหมด การอัปเดต และข้อมูลผู้ลงนาม
- PDF รายบุคคล/รายเคสยังแสดงข้อมูลการดูแลและลายเซ็นตามข้อมูลที่บันทึกไว้
