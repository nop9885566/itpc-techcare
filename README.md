# ITPC Techcare — ระบบบันทึกและติดตามการดูแลนักเรียนรายเคส

เว็บแอปพลิเคชันสำหรับครูที่ปรึกษาและผู้ดูแลโรงเรียน ITPC เพื่อใช้บันทึก นัดหมาย และติดตามผลการดูแลนักเรียนรายกรณี (รายเคส) ได้สะดวกรวดเร็วบนมือถือและคอมพิวเตอร์

---

## 🌟 ฟีเจอร์หลัก

1. **ระบบปฏิทินเคส (Calendar & Case Tracking)**
   - สลับมุมมองปฏิทินรายเดือน (Month View) และมุมมองรายการ (List View)
   - ไฮไลต์วันนี้ พร้อมตัวกรองดูเคส "ของฉัน" (ที่ได้รับมอบหมาย) หรือ "ทั้งหมด"
   - แต่ละเคสระบุประเภทและสถานะ (`planned` รอดำเนินการ / `done` เสร็จสิ้น)
   - ปุ่มลอย (+) สำหรับเพิ่มเคสใหม่ได้อย่างรวดเร็ว

2. **การบันทึกเคสการดูแล (Case Management)**
   - เลือกนักเรียนได้หลายคนต่อหนึ่งเคส (Many-to-Many) พร้อมค้นหาและกรองตามชั้น/ห้อง
   - เลือกประเภทเคส:
     - นักเรียนไม่มั่นใจในตัวเอง (`low_confidence`)
     - นักเรียนรู้สึกว่าตัวเองเรียนไม่เก่ง (`feel_not_smart`)
     - อื่นๆ (`other` พร้อมช่องระบุเพิ่มเติม)
   - เลือกผู้ดูแลได้มากกว่า 1 คน (ผู้สร้างจะถูกกำหนดเป็นผู้ดูแลคนแรกโดยอัตโนมัติ)
   - นัดหมายวัน-เวลา และบันทึกรายละเอียดเพิ่มเติม
   - แก้ไขและลบเคสได้ (มีกล่องยืนยันการลบ)

3. **บันทึกความคืบหน้า (Case Updates)**
   - เฉพาะผู้ดูแลที่เกี่ยวข้องกับเคสเท่านั้นที่มีสิทธิ์บันทึกอัปเดต
   - บันทึกสิ่งที่ทำ (กิจกรรม), ผลที่ได้ และขั้นตอนต่อไป
   - ตัวเลือกเปลี่ยนสถานะเคสเป็น "เสร็จสิ้น" ทันทีที่บันทึกความคืบหน้า

4. **ระบบเซ็นชื่อดิจิทัล (Digital Signatures)**
   - วาดลายเซ็นสดบนหน้าจอ (Touch / Mouse Canvas)
   - ระบุชื่อและบทบาทผู้เซ็น (เช่น นักเรียน, ผู้ปกครอง, ครูที่ปรึกษา, ผู้ดูแล)
   - เก็บภาพลายเซ็น (Base64 PNG) พร้อมวันที่เวลาที่เซ็น

5. **ระบบบริหารจัดการนักเรียน (Student Records)**
   - ค้นหาและกรองตามระดับชั้นและห้องเรียน
   - แสดงสถิติจำนวนเคสของนักเรียนแต่ละคน
   - หน้าประวัตินักเรียนแสดงไทม์ไลน์เคสทั้งหมดเรียงตามลำดับเวลา
   - เพิ่ม แก้ไข และลบข้อมูลนักเรียนได้

6. **การส่งออกรายงาน (PDF & Excel Export)**
   - **ส่งออก PDF รายเคส**: สรุปข้อมูลเคส นักเรียน ผู้ดูแล ประวัติการอัปเดต และลายเซ็นครบถ้วน
   - **ส่งออก PDF รายนักเรียน**: สรุปประวัติทุกเคสของนักเรียนคนนั้น
   - **ส่งออก Excel (.xlsx)**: ดาวน์โหลดไฟล์ Excel สำหรับเคสประจำเดือน หรือประวัติเคสรายนักเรียน
   - ภาษาไทยใน PDF แสดงผลถูกต้อง สระและวรรณยุกต์ไม่เพี้ยน

## 🛠 เทคโนโลยีที่ใช้

- **Frontend**: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS
- **Database**: Supabase (PostgreSQL) — **เชื่อมต่อผ่าน anon key เท่านั้น**
- **Icons**: Lucide React
- **Export & Canvas**: jsPDF, html2canvas, xlsx, signature_pad

## 🚀 ลำดับการติดตั้งและตั้งค่า

### 1. ติดตั้ง Dependencies
```bash
npm install
```

### 2. ตั้งค่าตัวแปรสภาพแวดล้อม (`.env.local`)
คัดลอกไฟล์ `.env.example` เป็น `.env.local`:
```bash
cp .env.example .env.local
```
จากนั้นแก้ไขค่าใน `.env.local` ด้วย URL และ anon key จาก Supabase Project ของคุณ:
```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here
```

## 🗄 ลำดับการรันสคริปต์ SQL (ใน Supabase SQL Editor)

ให้เปิด **Supabase Studio -> SQL Editor** แล้วรันไฟล์ในโฟลเดอร์ `sql/` ตามลำดับดังนี้:

1. `sql/01_schema.sql`  
   - เปิด Extension `pgcrypto` สำหรับการเข้ารหัส PIN
   - สร้างตาราง `students`, `caretakers`, `cases`, `case_students`, `case_caretakers`, `case_updates`, `case_signatures`
   - สร้าง Foreign Key Constraints, Indexes และ Trigger สำหรับอัปเดต `updated_at` อัตโนมัติ

2. `sql/02_rls_policies.sql`  
   - เปิด Row Level Security (RLS) บนทุกตาราง
   - กำหนดสิทธิ์ Policy ให้กับ `anon` ในการ Select / Insert / Update / Delete เท่าที่จำเป็น

3. `sql/03_functions.sql`  
   - ฟังก์ชัน `login_caretaker(p_name, p_pin)`: ตรวจสอบ PIN ผ่าน hash ในฐานข้อมูล โดยไม่ส่ง hash กลับมาฝั่งไคลเอนต์
   - ฟังก์ชัน `create_case_full(...)`: สร้างเคส พร้อมผูกความสัมพันธ์กับนักเรียนและผู้ดูแลภายใน Transaction เดียว
   - ฟังก์ชัน `update_case_full(...)`: แก้ไขข้อมูลเคสและอัปเดตรายการนักเรียน/ผู้ดูแล

4. `sql/04_seed.sql`  
   - สร้างข้อมูลตัวอย่าง:
     - ผู้ดูแล 3 ท่าน (ครูสมศรี, ครูวิชัย, ครูกานดา — **PIN เริ่มต้น: `1234`**)
     - นักเรียนตัวอย่าง 10 คน
     - เคสการดูแลตัวอย่าง 5 เคส พร้อมประวัติการอัปเดตและข้อมูลเชื่อมโยง

5. `sql/05_crud_examples.sql`  
   - รวมตัวอย่างคำสั่ง SQL (INSERT, UPDATE, DELETE) สำหรับทุกตาราง พร้อมคอมเมนต์ภาษาไทยสำหรับทดสอบรันใน Supabase

## 🔒 ข้อจำกัดด้านความปลอดภัยของการใช้ anon key เพียงอย่างเดียว

เนื่องจากโจทย์กำหนดให้เชื่อมต่อ Supabase ผ่าน **anon key เท่านั้น** โดยไม่ใช้ Supabase Auth (JWT session ของผู้ใช้จริง):

1. **การยืนยันตัวตนระดับแอปพลิเคชัน (Client-Side State)**
   - ข้อมูลผู้ใช้ที่เข้าสู่ระบบ (`id`, `name`) จะถูกบันทึกไว้ใน `localStorage` ของเบราว์เซอร์
   - หากผู้ใช้เปิดดูโค้ดหรือแก้ไข LocalStorage อาจสามารถเปลี่ยนผู้ดูแลที่แสดงผลในฝั่ง Client ได้
2. **สิทธิ์ระดับ RLS (Row Level Security)**
   - ฐานข้อมูลเห็นการเชื่อมต่อทุกคำขอมาจากบทบาท `anon` เดียวกัน
   - จึงต้องพึ่งพา PostgreSQL Functions (RPC) เช่น `login_caretaker` ในการตรวจสอบ hash และ `create_case_full` ในการจัดการข้อมูล
3. **การป้องกันระดับฐานข้อมูล**
   - รหัส PIN ถูก Hash ด้วยอัลกอริทึม `crypt()` ของ `pgcrypto` ฝั่งฐานข้อมูล
   - ไม่มีการส่งคอลัมน์ `pin_hash` กลับมายัง Client
   - มี Check constraints ตรวจสอบความถูกต้องของข้อมูล (เช่น `case_type`, `status`, `other_text`)

> **คำแนะนำสำหรับระบบ Production ในอนาคต**: หากต้องการความปลอดภัยสูงสุด แนะนำให้ต่อยอดโดยเปิดใช้งาน Supabase Auth หรือ Custom JWT เพื่อให้ RLS สามารถตรวจสอบ `auth.uid()` ของแต่ละบุคคลได้อย่างแท้จริงที่ระดับ Database Engine
